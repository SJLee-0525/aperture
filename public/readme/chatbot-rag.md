# 챗봇과 RAG

포트폴리오 챗봇은 사진, 음악, 개발 프로젝트와 프로필에서 질문에 맞는 내용을 찾고 답변과 참조 카드를 함께 반환합니다.

![챗봇 RAG 콘텐츠 동기화와 질문 처리 흐름도](./chatbot-flowchart.webp)

## 통합 검색과 챗봇의 차이

| 기능      | 처리 방식                              | 외부 모델 호출 |
| --------- | -------------------------------------- | -------------- |
| 통합 검색 | 공개 검색 문서를 브라우저에서 필터링   | 없음           |
| RAG 챗봇  | 질문과 관련된 청크를 찾은 뒤 답변 생성 | 있음           |

제목, 장소, 카메라, 기술명처럼 정확한 단어를 찾을 때는 `/search`가 빠릅니다. 여러 작업을 비교하거나 자연어로 설명을 요청할 때는 챗봇이 포트폴리오 문맥을 검색합니다.

## 콘텐츠 동기화

관리자가 콘텐츠를 저장하면 해당 원본을 의미 단위로 나눕니다. 프로젝트 하나도 개요, 담당 작업, 성과와 트러블슈팅이 서로 다른 청크가 될 수 있습니다.

각 청크에는 한국어와 영어, 검색에 필요한 메타데이터가 함께 들어갑니다. `text-embedding-3-small`이 기본 512차원 벡터를 만들고, 결과는 Firestore의 `ragDocuments`에 저장됩니다.

최초 설정이나 모델 변경 때는 전체 청크를 생성합니다. 이후에는 수정된 원본만 다시 처리하므로 사진 한 장을 바꿨을 때 전체 포트폴리오를 재임베딩하지 않습니다.

## 질문 처리

1. `/api/chat`이 요청 크기, 메시지 수, 언어와 요청 제한을 확인합니다.
2. 의도 분류기가 질문에 필요한 영역과 독립 검색어를 만듭니다.
3. 분류가 실패하거나 `none`이면 정규식 분류가 한 번 더 시도합니다.
4. 현재 공개된 포트폴리오 문맥이 필요하면 질문 임베딩과 키워드를 생성합니다.
5. 벡터 유사도와 키워드 점수를 합쳐 관련 청크를 최대 8개 선택합니다.
6. 기본 채팅 제공자가 답변을 스트리밍합니다.
7. 본문이 시작되기 전에 기본 제공자가 실패하면 폴백 제공자가 같은 입력을 처리합니다.
8. 서버가 링크와 참조 ID를 공개 데이터와 대조한 뒤 카드로 변환합니다.

## 하이브리드 검색

의미가 비슷한 표현은 벡터 점수로 찾고, 모델명이나 고유명사는 키워드 점수로 보강합니다.

```text
최종 점수 = 코사인 유사도 + (키워드 유사도 × 0.35)
```

벡터 점수 0.3 이상 또는 키워드 점수 0.5 이상인 결과 중 상위 8개를 답변 문맥으로 사용합니다. 질문과 무관한 전체 포트폴리오를 매번 모델에 보내지 않아 입력량과 혼선을 줄입니다.

## 캐시와 비용

Firestore의 벡터는 int8로 양자화한 스냅샷으로 압축해 1시간 동안 캐시합니다. 콘텐츠가 변경되면 같은 캐시 태그를 무효화합니다. 이 구조에서는 방문자 질문마다 Firestore의 모든 벡터를 다시 읽지 않습니다.

일반 검색은 임베딩이나 채팅 모델을 호출하지 않습니다. 운영 콘텐츠를 조회하는 RAG 질문에만 의도 분류, 질문 임베딩과 채팅 응답 비용이 발생합니다. mock 모드에서는 Firestore RAG와 질문 임베딩을 건너뜁니다.

## 실패 처리

| 상황                                | 처리                                   |
| ----------------------------------- | -------------------------------------- |
| 의도 분류 실패                      | 정규식 분류 사용                       |
| RAG 검색 실패                       | 섹션 요약 문맥으로 답변 계속           |
| 기본 제공자가 본문 전 실패          | 폴백 제공자로 전환                     |
| 기본 제공자가 이미 스트리밍 중 실패 | 다른 답변을 이어 붙이지 않고 오류 처리 |
| 참조 카드 조회 실패                 | 답변은 유지하고 카드만 제외            |
| 존재하지 않는 링크·참조 ID          | 응답에서 제거                          |

서버는 모델이 만든 링크와 참조를 공개 데이터와 다시 대조합니다. 내부 경로 allowlist에 포함되고 현재 공개된 데이터만 방문자에게 전달합니다.
