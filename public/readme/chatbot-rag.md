# 챗봇과 RAG

포트폴리오 챗봇은 질문을 보낸 화면과 포트폴리오 검색 결과를 함께 참고합니다. 열린 사진, 연주, 수상 내역, 프로젝트, 블로그 글은 ID로 직접 조회하고, 열린 블로그 글은 본문 전체를 문맥으로 읽습니다. 범위가 넓은 질문은 RAG로 관련 청크를 찾습니다. 모델이 만든 링크, 참조 카드, 연락 초안은 서버 검증을 통과한 것만 화면에 표시합니다.

![화면 문맥과 RAG를 포함한 챗봇 처리 흐름도](./chatbot-flowchart.webp)

## 세 가지 조회 경로

| 기능      | 처리 방식                                                  | 외부 모델 호출          |
| --------- | ---------------------------------------------------------- | ----------------------- |
| 통합 검색 | 검색 문서는 브라우저에서, 블로그 본문 일치는 서버에서 대조 | 없음                    |
| 화면 문맥 | URL의 항목 ID를 공개 데이터에서 직접 조회                  | 챗봇 응답 생성에만 사용 |
| RAG 챗봇  | 질문과 관련된 청크를 찾은 뒤 답변 생성                     | 있음                    |

제목, 장소, 카메라, 기술명처럼 정확한 단어를 찾을 때는 `/search`가 빠릅니다. 열린 항목을 가리켜 질문하면 화면 문맥을 우선하고, 여러 작업을 비교하거나 설명을 요청하면 RAG가 포트폴리오 문맥을 보강합니다.

## 콘텐츠 동기화

관리자가 콘텐츠를 저장하면 원본을 의미 단위로 나눕니다. 프로젝트 하나도 개요, 담당 작업, 성과, 트러블슈팅이 서로 다른 청크가 될 수 있습니다.

각 청크에는 한국어와 영어, 검색 메타데이터가 함께 들어갑니다. `text-embedding-3-small`이 기본 512차원 벡터를 만들고, 결과는 Postgres의 `rag_documents` 테이블(pgvector)에 저장됩니다.

최초 설정이나 모델 변경 때는 전체 청크를 생성합니다. 이후에는 수정된 원본만 다시 처리하므로 사진 한 장을 바꿔도 전체 포트폴리오를 재임베딩하지 않습니다.

## 질문 처리

1. 클라이언트가 전송 순간의 `pathname`과 열린 항목의 type·ID를 요청에 넣습니다. 사용자 메시지에는 항목 이름과 원래 URL을 따로 기록해, 어떤 화면과 함께 보냈는지 확인하고 다시 돌아갈 수 있습니다. 이 표시 정보는 모델 대화 이력에 넣지 않습니다.
2. `/api/chat`이 요청 크기, 메시지 수, 언어, 화면 문맥 형식과 IP당 분당 10회·전역 일일 1,000회 요청 제한을 검사합니다.
3. 서버는 화면 경로와 type이 맞을 때만 ID를 공개 데이터에서 직접 조회합니다. 최신 데이터 조회가 실패하면 캐시를 사용하고, 항목을 찾지 못해도 화면 문맥 없이 답변을 계속합니다.
4. 의도 분류기가 질문에 필요한 영역과 독립 검색어를 만듭니다. 분류가 실패하거나 검색 영역이 없으면 정규식 분류로 보완합니다.
5. 포트폴리오 검색이 필요하면 질문 임베딩으로 pgvector 검색이 상위 후보를 조회하고, 키워드 점수를 합쳐 관련 청크를 최대 10개 선택합니다.
6. 화면 문맥과 RAG 문맥을 프롬프트에 넣습니다. "이 사진", "이 프로젝트"처럼 열린 항목을 가리키는 질문에는 화면 문맥을 우선합니다.
7. 기본 채팅 제공자가 답변을 스트리밍합니다. 본문을 보내기 전에 실패하면 폴백 제공자가 같은 입력을 처리합니다.
8. 서버가 내부 링크, 참조 ID, 연락 초안을 검증합니다. 잘린 구조화 응답에서는 본문만 복구하고 나머지 필드는 버립니다.
9. 클라이언트는 검증된 답변, 링크, 참조 카드와 연락 초안 버튼을 표시합니다.

## 화면 문맥과 메시지 기록

`ChatContext`에는 공개 경로와 열린 대상 하나만 들어갑니다. 사진 필터는 같은 URL에 있으므로 요청 필드에 복제하지 않습니다.

```ts
type ChatContext = {
  pathname: string;
  openTarget?: {
    type: "photo" | "work" | "award" | "project" | "article";
    id: string;
  };
};
```

화면 문맥은 RAG와 다른 경로로 처리합니다. 항목 ID가 있으면 서버가 사진, 연주, 음악 수상, 프로젝트, 블로그 글의 공개 데이터에서 직접 찾습니다. 조회 결과는 짧은 `SCREEN_CONTEXT`로 만들고, 세부 설명이 더 필요할 때 RAG가 보강합니다. 블로그 글은 본문 평문 전체(최대 50,000자)를 함께 실으며, 이 경우 같은 글의 RAG 청크는 중복이라 제외합니다.

사용자 메시지에 보이는 "함께 보낸" 기록은 클라이언트 세션의 표시용 스냅샷입니다. 전송 당시의 `pathname + search`를 저장하므로 항목을 누르면 사진 필터와 앨범 상태를 포함한 원래 화면으로 돌아갑니다. 재시도할 때는 저장된 스냅샷이 아니라 그 시점의 URL을 다시 읽습니다.

## 하이브리드 검색

의미가 비슷한 표현은 벡터 점수로 찾고, 모델명이나 고유명사는 키워드 점수로 보강합니다.

```text
최종 점수 = 코사인 유사도 + (키워드 유사도 × 0.35)
```

질문 벡터와 가까운 상위 40개 후보를 pgvector에서 조회하고, 벡터 점수 0.3 이상 또는 키워드 점수 0.5 이상인 결과 중 상위 10개를 답변 문맥으로 사용합니다. 질문과 무관한 전체 포트폴리오를 매번 모델에 보내지 않아 입력량과 혼선을 줄입니다.

## 응답 검증과 후속 동작

| 응답 필드 | 검증과 표시 방식                                                                                                                                        |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 내부 링크 | 공개 경로 allowlist를 확인합니다. 사진 필터 query는 공개 태그·카메라와 초점거리 범위를 대조한 뒤 canonical URL로 다시 만듭니다.                         |
| 참조 ID   | 현재 공개된 사진·연주·프로젝트·블로그 글을 다시 조회해 최대 3개의 참조 카드로 표시합니다. 찾지 못한 ID는 제거합니다.                                    |
| 연락 초안 | 이름·이메일·메시지 형식과 길이를 검사합니다. 방문자가 버튼을 눌렀을 때만 `sessionStorage`에 최대 10분 보관하고, 연락 페이지가 한 번 읽은 뒤 삭제합니다. |

연락 초안 저장에 실패해도 일반 연락 페이지로 이동합니다. 캡차 확인과 전송은 방문자가 직접 해야 하며, 챗봇이 폼을 자동 제출하지 않습니다.

## 캐시와 비용

벡터는 Postgres에 있고 질문마다 벡터 검색 한 번으로 후보를 조회합니다. 스냅샷 캐시가 없어 콘텐츠 변경이 다음 질문에 바로 반영됩니다. 프로필 요약 문맥은 1시간 캐시하고 콘텐츠가 변경되면 무효화합니다.

통합 검색과 화면 항목 조회 자체는 임베딩 모델을 호출하지 않습니다. 운영 콘텐츠를 조회하는 RAG 질문에만 의도 분류와 질문 임베딩 비용이 추가됩니다. mock 모드에서는 RAG와 질문 임베딩을 건너뜁니다.

## 실패 처리

| 상황                                | 처리                                     |
| ----------------------------------- | ---------------------------------------- |
| 화면 데이터 최신 조회 실패          | 캐시된 공개 데이터로 다시 조회           |
| 화면 항목을 찾지 못함               | 화면 문맥 없이 답변 계속                 |
| 의도 분류 실패                      | 정규식 분류 사용                         |
| RAG 검색 실패                       | 섹션 요약 문맥으로 답변 계속             |
| 기본 제공자가 본문 전 실패          | 폴백 제공자로 전환                       |
| 기본 제공자가 이미 스트리밍 중 실패 | 다른 답변을 이어 붙이지 않고 오류 처리   |
| 구조화 응답이 일부만 복구됨         | 본문만 사용하고 링크·참조·연락 초안 제거 |
| 링크·참조 ID 검증 실패              | 답변은 유지하고 해당 항목만 제거         |
| 연락 초안 저장 실패                 | 초안 없이 일반 연락 페이지로 이동        |
