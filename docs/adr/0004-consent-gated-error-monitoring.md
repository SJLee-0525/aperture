# ADR-0004: 동의 기반 오류 모니터링

## Status

Accepted, 2026-08-10

2026-08-18 보완: [ADR-0006](0006-ai-error-triage-alerts.md)이 오류 데이터의 수신자를 확장한다.
Sentry가 수집한 이벤트 중 화이트리스트로 추린 항목이 LLM 제공자(OpenAI·Google)로 한 번 더 나간다.
이 ADR의 최소 수집 원칙은 그 경로에도 그대로 적용되며, 아래 결정은 모두 유효하다.
수신자 확장이 실제로 발생하는 시점은 [plan 10](../plan/10-sentry-ai-triage.md)의 배포 이후이고,
처리방침(`src/features/legal/_lib/legal-documents.tsx`) 갱신은 그 배포와 같은 변경에 포함한다.

## Context

공개 페이지의 브라우저 오류는 방문자의 선택 없이 외부로 보내지 않는다. 관리자 CMS와 서버 오류는
운영에 필요하지만, 문의·챗봇·인증 데이터가 오류 이벤트나 화면 기록에 섞여서는 안 된다. Sentry Replay는
브라우저 클라이언트를 닫아도 녹화 리스너는 남는다. 따라서 동의 철회와 공개/admin 전환을 별도로
관리해야 한다.

## Decision

- `@sentry/nextjs`를 사용하고 브라우저 이벤트는 동일 출처 `/monitoring` 터널로 보낸다.
- 공개 브라우저 SDK는 오류 보고 동의를 받은 뒤에만 동적 import한다. 동의 전에는 SDK 청크와 Sentry 요청이
  없다.
- `ap-consent:v3`에 방문 분석과 오류 보고 선택을 따로 저장한다. v1·v2 단일 선택은 승계하지 않는다.
- Sentry 오류 보고 동의에는 이전 국가, 수신자, 항목, 시점·방법, 목적·보유기간과 거부 효과를 표시한다.
  `NEXT_PUBLIC_SENTRY_DATA_REGION`이 없으면 Sentry는 비활성화한다.
- Replay는 공개 페이지의 오류 세션에만 사용한다. 입력값을 마스킹하고 챗봇 패널을 차단하며, 검색어·토큰이
  든 URL은 Replay 전용 콜백에서 정제한다.
- 철회 또는 admin 전환 때 Replay를 명시적으로 `stop()`하고 세션 저장값을 지운 뒤 클라이언트를 닫는다.
- 관리자 브라우저 모니터링은 `AuthGuard`가 관리자 UID를 확인한 뒤에만 시작하며 Replay는 사용하지 않는다.
  `/admin/login`과 인증 대기 화면에서는 시작하지 않는다.
- 서버·엣지 오류는 동의와 무관하게 수집하되 `dataCollection`의 모든 데이터 범주를 명시적으로 최소화한다.
  헤더, 쿠키, 본문, 쿼리, GraphQL/AI 입력·출력, DB 데이터와 스택 로컬 변수는 수집하지 않는다.
- 성능 추적은 끈다. 릴리즈 이름과 소스맵은 빌드 플러그인이 관리한다.
- `@opentelemetry/core` 2.x를 직접 고정한다. Sentry의 선택적 peer가 `firebase-tools`의 취약한
  개발 전용 1.x를 운영 경로에서 재사용하지 않게 하기 위한 설치 계약이며 앱 코드에서는 import하지 않는다.

## Consequences

- 미동의 방문자의 브라우저 오류는 관측하지 못한다.
- Sentry/Replay 청크는 동의 후에 내려받으므로 초기 번들 크기는 늘지 않는다.
- 환경변수 변경은 재배포 뒤 적용된다. 긴급 중지는 DSN 또는 데이터 지역을 제거하고 재배포한다.
- 배포 전 Sentry 데이터 지역, 보관기간, 서버 측 스크럽과 실제 Replay 마스킹을 대시보드에서 확인해야 한다.
