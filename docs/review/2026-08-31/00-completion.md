## 0. 용어부터

이 검토에 나오는 말 넷을 먼저 풀어 둔다.

- **파이프라인 3개**: 이 저장소에는 문제를 발견하면 Discord 로 카드를 보내는 자동 알림이
  셋 있다. Sentry 오류 알림, 주간 의존성 보안 리포트, Core Web Vitals(웹 성능) 알림이다.
- **트리아지**: 문제가 얼마나 급한지 먼저 가려내는 일. 여기서는 AI 가 경고를 읽고
  원인 후보와 확인 순서를 카드에 적어 준다.
- **embed**: Discord 카드 한 장의 데이터 형식. 제목·본문·항목마다 글자 수 상한이 있고,
  하나라도 넘으면 Discord 가 카드 전체를 거부한다(400 오류).
- **provider**: AI 호출 담당. OpenAI 나 Gemini 를 쓰고, 첫 시도가 실패하면 예비(폴백)를
  한 번 더 시도한다.

## 2. 지금 할 것

순서대로 둘이고, 2.3 이 실행하면서 지우는 확인 목록이다.

### 2.1 남은 커밋과 push

구조 라운드에서 후보 3(타입 소유권 이동)만 `c0d04bc` 로 커밋됐다. embed 예산
(`lib/discord/embed-budget`), 공용 전송(`lib/triage`), 계열 전환, 문서
(ADR-0007 · [03-resolution](03-resolution.md) · 이 문서)가 작업 트리에 있다.

### 2.2 push 후 수동 dispatch 2건

단위 테스트로 닿지 않는 것들이 남아 있다. 아래 둘을 손으로 실행해서 확인한다.

```
gh workflow run core-web-vitals-report.yml -f force_ai_analysis=true
gh workflow run dependency-security-report.yml
```

이 실행이 확인하는 것: 올린 액션 버전(`checkout@v7`·`setup-node@v6`)으로 job 이
통과하는지, Discord 에 카드가 실제로 도착하는지, 실행 결과 보관함(artifact)에 AI 분석이
남는지, 새 Lighthouse 병합 계약이 통과하는지, 강제 실행 뒤 같은 경고가 중복 전송되지
않는지(C5)다.

주의: `force_ai_analysis=true` 는 실제 AI 호출 비용과 실제 Discord 알림을 만든다.
그리고 이 실행은 배포가 잘 되는지 보는 smoke test 이지, C1 같은 결함의 재현이 아니다.
결함 회귀는 단위 테스트가 막는다.

### 2.3 확인 체크리스트

세 resolution 문서가 남긴 미확인 항목을 한 목록으로 모았다. 실행하면서 하나씩 지운다.

배포 전:

- [ ] 남은 변경을 커밋하고 push 한다 (2.1).
- [x] 등록된 환경변수(GitHub secret·variable, Vercel)는 갱신할 것이 없다. 워크플로가
      넘기는 env 키와 코드가 읽는 이름을 대조해 확인했다(2026-08-31). 이름을 바꾸지
      않는 것은 ADR-0007 결정 5다.

dispatch 1, `core-web-vitals-report.yml` (`force_ai_analysis=true`):

- [ ] 올린 액션 버전(`checkout@v7`·`setup-node@v6`)으로 job 이 통과한다.
- [ ] `Merge Lighthouse shards` 단계가 새 병합 계약으로 통과한다.
- [ ] Discord 에 카드가 도착한다.
- [ ] Actions summary 와 `core-web-vitals-ai-report` artifact 에 AI 분석이 남는다.
- [ ] snapshot 의 `sentAlerts` 에 이번 경고 key 가 들어가고, 이어지는 정기 실행이 같은
      회귀로 카드를 다시 보내지 않는다 (C5).
- [ ] 경고가 2개 이상이면 통합 카드의 `가장 크게 악화` 줄과 `상세` 링크를 확인한다
      (C12·C13). 경고가 하나뿐이면 통합 카드가 오지 않으므로 건너뛴다.

dispatch 2, `dependency-security-report.yml`:

- [ ] Discord 에 주간 리포트 카드가 도착한다.

여기까지가 이 검토가 남긴 몫이다. 나머지 운영 검증(secret 마스킹, fallback 카드,
다음 예약 실행의 snapshot 비교 등)은
[checklist 11 §4.3](../../checklist/11-core-web-vitals-ai-alerts.md#43-수동-운영-검증) 의
미체크 항목이 소유하며, 위 dispatch 가 그중 일부를 함께 닫는다.

## 4. 확인하지 못한 것

닫았다고 적은 것과 확인하지 못한 것을 섞지 않는다. 아래 셋은 아직 실측이 없다.

- **실제 Discord 도착, 워크플로 실행, AI 응답 분포.** 2.2 의 dispatch 가 덮는다.
- **Discord 400 실측.** C1 은 Discord 의 문서화된 계약과 코드 경로로 세웠고, 실제로 빈
  field 를 보내 400 을 받아 본 적은 없다([07 보류](07-rejected.md#보류)).
- **`redactPerformanceError` 의 실제 유출 경로.** 웹훅 URL 이 오류 메시지에 실려 나가는
  경로를 끝내 찾지 못했다. 그래도 같은 목적의 방어 둘이 강도가 달랐던 것 자체를 고쳤다.
