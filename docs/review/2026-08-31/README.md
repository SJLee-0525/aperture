## 지금 고칠 두 가지

둘 다 Core Web Vitals 알림 경로이고 둘 다 한 파일 국소 수정이다.

1. **AI 카드가 Discord 400으로 통째로 실패할 수 있다.** 모델이 `inspectFirst` 와
   `recommendedChecks` 를 모두 빈 배열로 돌려주면 embed field 의 `value` 가 빈 문자열이 된다.
   Discord 는 이 필드를 거부하고, 400 은 재시도 대상이 아니라서 실행이 실패한 채 끝난다.
   대상이 하나일 때만 쓰이는 경로인데, 그게 가장 흔한 경우다.
   → [02](02-correctness.md#c1-빈-목록이-discord-400-을-만들고-알림이-사라진다)
2. **대상이 21개를 넘으면 AI 분석이 항상 사라진다.** 프롬프트는 20개로 자르는데 파서에는
   자르기 전 개수가 들어간다. `force_ai_analysis` 는 중복 억제를 건너뛰어 현재 경고 전부를
   한 번에 올리므로, 이 조건은 예외가 아니라 강제 실행의 정상 동작이다.
   → [02](02-correctness.md#c2-대상이-21개를-넘으면-ai-분석이-항상-버려진다)

## 이 저장소가 잘하고 있는 것

두 렌즈에서 독립적으로 확인된 것만 적는다.

- **ZIP 을 디스크에 풀지 않는다.** `snapshot-archive.ts` 가 entry 이름을 먼저 확인하고
  `unzip -p` 로 stdout 만 읽는다. 상위 경로 entry 가 성립할 자리가 없다.
- **멘션을 미리 닫아 뒀다.** `send-webhook.ts:72-74` 가 아직 `content` 를 쓰지 않는데도
  `allowed_mentions: { parse: [] }` 를 넣고, 왜 지금 필요 없는 방어를 넣었는지 주석에 적었다.
- **키를 query 에 싣지 않는다.** CrUX 와 Gemini 모두 헤더로 보내고 이유를 주석에 남겼다.
  OpenAI 세 곳 전부 `store: false` 다.
- **워크플로 권한이 최소다.** 두 파일 모두 `permissions:` 를 명시하고 필요한 것만 켠다.
- **신규 파이프라인이 인바운드 표면을 늘리지 않았다.** 둘 다 pull 기반이라 웹훅을 더 열지 않았다.
- **테스트가 형식적이지 않다.** 370개가 파서 경계값, 리다이렉트 루프, 예산 초과, 서명 검증을
  실제로 단언한다. 문제는 품질이 아니라 두 곳의 빈 배열 케이스가 비어 있다는 것이다.
