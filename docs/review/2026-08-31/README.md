## 먼저 알아둘 것

**자동 검사는 전부 통과한다.** 범위 내 테스트 41 파일 475개가 1.68초에 통과하고,
ESLint 0건이며, 두 워크플로 모두 실제 실행 이력이 성공이다.
아래 항목은 전부 도구가 못 보는 층위에서 나왔다.

검토 중에 통합 카드와 강제 재분석을 고치는 `84509d7` 이 들어와 전 항목을 다시 대조했다.
세 건이 닫혔고, 한 건은 범위가 넓어졌으며, 새 코드에서 두 건이 나왔다.
이어서 보안 라운드(`d252f81`~~`33b1ab9`)가 01 문서의 넷과 02 문서의 C1 을 닫았고,
정확성 라운드(`3658a56`~~`2f7044b`)가 02 문서의 남은 아홉 건을 닫았다.
그 라운드에서 검토가 못 본 두 건(C14·C15)이 나와 같은 커밋들에서 함께 닫혔다.

| 낮음   | 1    | S2 호출 상한. 시크릿 등록이 선행 조건이라 미구현 |
| 처리됨 | 19   | 02 의 C1~C15 전부, 01 의 S1·S3·S4·S5             |

**보안 결함은 없다.** 신뢰 경계 7개를 STRIDE로 훑어 다섯 건을 적었고 침해 경로는 없었다.
넷은 닫았고 남은 S2(호출 상한 없음)는 낮음이다. cron 자기 트리거라 위협 모델이 sentry 와
다르고, 상한을 실제로 걸려면 워크플로에 Upstash 시크릿 등록이 선행돼야 한다.
zip 처리, 리다이렉트 인증, 멘션 봉쇄, 키 전송은 전부 의도대로 동작한다.

## 지금 고칠 것

**결함도 구조 후보도 남아 있지 않다.** 두 라운드가 01 과 02 의 항목을 모두 닫았고,
구조 라운드가 [03](03-architecture.md) 의 후보 넷을 닫았다. 트리아지 전송은
`lib/triage`([ADR-0007](../../adr/0007-shared-triage-transport.md)), embed 예산은
`lib/discord/embed-budget` 한 벌이다. 처리 내역은 [03-resolution.md](03-resolution.md).

남은 것은 둘이다. S2(호출 상한)는 낮음이며 워크플로에 Upstash 시크릿을 등록하기로
정해야 착수할 수 있다. 그리고 push 이후 수동 dispatch 로 실제 Discord 도착과
artifact 기록을 확인해야 한다(01·03 resolution 의 미확인 항목).

정확성 라운드가 무엇을 어떻게 닫았는지는 [02-resolution.md](02-resolution.md) 에 있다.

## 이 저장소가 잘하고 있는 것

두 렌즈에서 독립적으로 확인된 것만 적는다.

- **ZIP 을 디스크에 풀지 않는다.** `snapshot-archive.ts` 가 entry 이름을 먼저 확인하고
  `unzip -p` 로 stdout 만 읽는다. 상위 경로 entry 가 성립할 자리가 없다.
- **멘션을 미리 닫아 뒀다.** `send-webhook.ts:72-74` 가 아직 `content` 를 쓰지 않는데도
  `allowed_mentions: { parse: [] }` 를 넣고, 왜 지금 필요 없는 방어를 넣었는지 주석에 적었다.
- **키를 query 에 싣지 않는다.** CrUX 와 Gemini 모두 헤더로 보내고 이유를 주석에 남겼다.
  OpenAI 세 곳 전부 `store: false` 다.
- **워크플로 권한이 최소다.** 두 파일 모두 `permissions:` 를 명시하고 필요한 것만 켠다.
- **신규 파이프라인이 인바운드 표면을 늘리지 않았다.** 둘 다 pull 기반이라 웹훅을 더 열지 않았다.
- **테스트가 형식적이지 않다.** 475개가 파서 경계값, 리다이렉트 루프, 예산 초과, 서명 검증을
  실제로 단언한다. 처음 지적한 빈 배열 케이스 두 곳은 두 라운드에서 채워졌다.
