# 기술 스택 업로드 가이드 (공개 화면 `/dev/career`)

관리자 페이지: `/admin/dev/config`

각 카테고리에서 기술명을 입력하고 `배경`, `글자` 색상에 아래 HEX 값을 넣는다. RGB 값은 색상 확인 및 다른 입력 UI용이다. 현재 관리자 색상 선택기는 HEX 형식(`#RRGGBB`)으로 저장한다.

## 색 대비 기준 ★

칩 글자는 13px 안팎이라 WCAG 2 AA 의 일반 텍스트 기준인 **배경 대 글자 대비 4.5:1 이상**을 만족해야 한다. 아래 표의 값은 모두 이 기준을 통과한다. 표에 없는 기술을 추가할 때는 브랜드 색을 그대로 쓰지 말고 대비를 먼저 확인한다.

- 브랜드 색이 밝아 흰 글자가 미달하면 글자를 검정으로 바꾸거나, 같은 계열의 더 어두운 색을 쓴다. 예: Google Gemini 는 브랜드 파랑 `#4285F4`(흰 글자 3.56:1)가 미달이라 더 어두운 `#1967D2`(5.37:1)를 쓴다. PostgreSQL 도 `#4169E1` + 검정 글자가 4.33:1 이라 공식 브랜드 색 `#336791` + 흰 글자(6.02:1)를 쓴다.
- `/dev/career` 는 `e2e/accessibility.e2e.ts` 의 axe 스캔 대상이라 미달 조합을 올리면 접근성 테스트가 실패한다. 실패 메시지에 해당 칩의 기술명과 실제 대비 값이 찍힌다.
- mock 데이터(`src/mocks/dev.ts`)의 스택 색도 같은 기준을 따른다. 표를 고치면 mock 도 함께 맞춘다.

## 저장 순서

1. `/admin/dev/config`에 로그인한다.
2. 위 순서대로 카테고리를 추가한다.
3. 각 기술의 이름과 배경/글자 HEX 값을 입력한다.
4. 표에 없는 색을 넣었다면 「색 대비 기준」의 4.5:1 을 만족하는지 확인한다.
5. 페이지 아래의 저장 버튼을 누른다.
6. `/dev/career` 아래쪽 「기술」 섹션에서 반영 결과를 확인한다.
7. 색을 새로 추가했다면 `npm run test:a11y` 로 대비 위반이 없는지 확인한다.
