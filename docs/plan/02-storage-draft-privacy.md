# Storage 초안 이미지 비공개화 계획

## 상태

보류. 현재 이미지는 기밀 자료가 아니고 객체명도 UUID이므로, 읽기 비용과 구현 복잡도를 늘리지 않는 기존 정책을 당분간 유지한다.

현재 `storage.rules`는 객체 목록 조회와 쓰기를 관리자에게만 허용하지만, 개별 객체 GET은 모든 경로에서 공개한다. 따라서 Firestore 초안 문서가 비공개여도 이미지 URL이나 전체 객체 경로를 아는 사람은 이미지를 내려받을 수 있다.

## 결정 원칙

- Storage Rules에서 이미지 요청마다 Firestore 문서를 조회해 `published`를 확인하지 않는다.
  - 이미지 요청량에 비례해 Firestore Rules 종속 읽기가 늘어날 수 있다.
  - 이미지 경로와 여러 콘텐츠 컬렉션의 문서 관계가 Rules에 중복된다.
- 공개와 초안 객체를 경로로 분리한다.
- 발행 전환은 복사 → Firestore 갱신 → 이전 객체 삭제 순서로 수행해 깨진 공개 URL을 만들지 않는다.
- 실패 시 원래 문서와 객체가 남도록 보상 동작을 설계한다.

## 목표 구조

```text
draft/photos/{photoId}/...
draft/music/{workId}/...
draft/dev/{projectId}/...

public/photos/{photoId}/...
public/music/{workId}/...
public/dev/{projectId}/...
```

Storage Rules는 `public/**`의 GET만 익명 허용하고 `draft/**`의 GET·LIST·WRITE는 관리자에게만 허용한다.

## 구현 단계

1. 업로드 함수가 문서의 공개 상태에 따라 `draft/` 또는 `public/` 경로를 사용하도록 경로 생성을 분리한다.
2. 사진·음악·개발의 발행 상태 변경을 공통 자산 전환 함수로 감싼다.
3. 각 원본·preview·thumbnail을 대상 경로로 복사하고 새 다운로드 URL을 준비한다.
4. 콘텐츠 문서의 이미지 메타데이터와 `published`를 한 번의 Firestore 문서 갱신에 반영한다.
5. 문서 갱신 성공 후 이전 경로 객체를 삭제한다. 삭제 실패는 정리 가능한 고아 객체로 기록하고 공개 동작은 유지한다.
6. 기존 객체를 경로별로 이관하는 관리자용 일회성 마이그레이션을 만든다.
7. Firestore·Storage 에뮬레이터 테스트에 다음 회귀 조건을 추가한다.
   - 비로그인은 `public/**`만 GET 가능
   - 초안과 목록 조회는 관리자만 가능
   - 발행·발행 취소 후 문서 URL과 실제 객체가 일치
   - 복사나 문서 갱신 실패 시 기존 이미지가 사라지지 않음

## 비용과 작업량

- Firestore: 발행 상태 변경 시 현재의 문서 갱신과 이미지 URL 갱신을 합치면 문서 쓰기 횟수는 항목당 1회를 유지할 수 있다.
- Storage: 발행·발행 취소마다 이미지 파생본 수만큼 복사와 삭제가 발생한다. 프로젝트의 다중 이미지가 가장 큰 작업 단위다.
- 공개 이미지 요청에는 Firestore 종속 읽기를 추가하지 않는다.
- 예상 작업량은 중간 이상이다. 경로 변경보다 기존 데이터 마이그레이션, 중간 실패 복구, 세 콘텐츠 유형의 자산 생명주기 테스트가 대부분을 차지한다.

## 실행 전 확인

- Firebase Storage의 실제 복사 방식과 요금 산정
- 발행 취소 시 공개 URL을 즉시 폐기할지, 일정 기간 유지할지
- 기존 CDN 캐시와 삭제된 다운로드 URL의 잔존 시간
- 마이그레이션 중 신규 관리자 편집을 잠시 막을지 여부
